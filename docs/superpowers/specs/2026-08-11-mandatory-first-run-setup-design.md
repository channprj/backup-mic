# Backup Mic 필수 첫 실행 설정 및 상태바 아이콘 설계

## 배경

Backup Mic은 저장된 백업 폴더가 없으면 백업을 거부하고 첫 실행 창을 유지하지만, 현재는 폴더 선택이 끝나는 즉시 설정이 완료된 것으로 간주한다. 사용자는 폴더 선택을 취소할 수 있어야 하지만, 폴더를 확정하고 기본 설정을 점검하기 전에는 일반 화면이나 백업 기능을 사용할 수 없어야 한다.

이 변경은 새 설치에만 필수 온보딩을 적용한다. 이미 백업 폴더가 저장된 기존 설치와 `com.channprj.DJIMicBackup`에서 마이그레이션한 설치는 현재 설정을 유지하며 추가 확인을 요구하지 않는다.

## 목표

- 새 설치에서 백업 폴더 선택과 기본 설정 점검을 모두 완료해야 앱을 사용할 수 있게 한다.
- 폴더 선택창 취소를 허용하되, 차단된 온보딩 화면으로 돌아오게 한다.
- 온보딩 도중 종료하거나 강제 종료해도 다음 실행에서 정확한 단계부터 이어간다.
- Rust 백엔드에서 수동·자동 백업을 모두 차단해 UI 우회로가 생기지 않게 한다.
- 기존 설치, 마이그레이션된 destination, 기존 사용자 설정과 백업 증거를 변경하지 않는다.
- 설정 점검에서 실제 저장된 기본값을 확인하고 수정할 수 있게 한다.
- 앱 아이콘의 얼굴 심볼을 macOS 상태바에 표시하고 시스템 테마에 맞춰 자동 반전한다.

## 범위 밖

- 기존 사용자에게 업데이트 후 설정 점검을 다시 요구하지 않는다.
- 매 실행마다 설정 확인을 요구하지 않는다.
- 원본 휴지통 이동의 검증 조건이나 기본값을 바꾸지 않는다.
- 백업 폴더의 기본 경로를 자동 확정하지 않는다.
- 온보딩을 별도의 창이나 다단계 범용 프레임워크로 확장하지 않는다.
- 앱 번들 아이콘 자체의 색상이나 형태를 변경하지 않는다.
- 상태바 아이콘을 위해 별도 테마 감지, JavaScript 이벤트 또는 수동 색상 전환을 도입하지 않는다.

## 상태 모델

공개 `setup_state`는 다음 세 상태를 사용한다.

1. `needs_destination`: 유효하게 저장된 백업 폴더가 없다.
2. `needs_settings_review`: 새 설치가 폴더를 저장했지만 기본 설정 점검을 완료하지 않았다.
3. `ready`: 정상 화면과 백업 작업을 사용할 수 있다.

상태 전이는 단방향 첫 실행 흐름을 따른다.

```text
needs_destination
  -> 폴더 선택 및 검증 성공
needs_settings_review
  -> 설정 확인 완료 영구 저장
ready
```

폴더 선택 취소나 검증 실패는 `needs_destination`을 유지한다. 설정 저장 실패나 완료 명령 실패는 `needs_settings_review`를 유지한다. 목적지 변경처럼 기존 `ready` 사용자가 수행하는 일반 설정은 온보딩 상태를 되돌리지 않는다.

## 영구 저장과 기존 설치 호환성

SQLite settings에 앱이 관리하는 첫 실행 표식을 저장한다. 값은 `settings_review_pending` 또는 `complete` 중 하나이며, 임의 문자열이나 잘못된 JSON은 안전한 오류로 처리한다.

시작 상태는 destination과 표식을 함께 해석한다.

| 저장된 destination | 첫 실행 표식 | 시작 상태 |
| --- | --- | --- |
| 없음 또는 유효하지 않음 | 없음 | `needs_destination` |
| 없음 또는 유효하지 않음 | `settings_review_pending` | `needs_destination` |
| 없음 또는 유효하지 않음 | `complete` | `needs_destination` |
| 있음 | 없음 | `ready` |
| 있음 | `settings_review_pending` | `needs_settings_review` |
| 있음 | `complete` | `ready` |

`destination 있음 + 표식 없음`을 `ready`로 보는 규칙이 기존 설치 호환성 경계다. 마이그레이션된 ledger에도 별도 백필을 하지 않는다.

새 설치가 처음 destination을 확정할 때 destination과 `settings_review_pending`을 같은 SQLite transaction에 저장한다. 따라서 비정상 종료 뒤에 destination만 저장되고 일반 화면이 열리는 중간 상태를 만들지 않는다. 이미 `ready`인 사용자가 설정에서 destination을 바꿀 때는 기존 완료 상태를 보존한다.

## Rust 백엔드 계약

`AppState`는 destination 설정 여부와 첫 실행 표식으로 `SetupStateDto`를 구성한다. `backup_is_ready`는 유효한 destination, 연결된 규칙 source, destination/source 분리에 더해 `setup_state == ready`를 요구한다.

새 `complete_initial_setup` 명령은 다음 조건을 모두 만족할 때만 성공한다.

- 현재 상태가 `needs_settings_review`다.
- destination이 여전히 설정되어 있고 사용할 수 있다.
- 저장된 첫 실행 표식이 `settings_review_pending`이다.

명령은 `complete`를 먼저 SQLite에 저장한 다음 runtime snapshot을 `ready`로 바꾼다. 저장 실패 시 snapshot을 앞서 변경하지 않는다. 완료 후 자동 백업이 켜져 있고 일치하는 녹음기가 연결되어 있으면 기존 작업 예약과 직렬화 규칙을 통해 백업 시작을 요청한다.

첫 폴더 선택 직후에는 자동 백업을 시작하지 않는다. 기존 `ready` 사용자가 destination을 변경한 경우에만 현재의 변경 후 자동 백업 동작을 유지한다.

## 첫 실행 UI

메인 popover는 `setup_state`가 `ready`가 아닐 때 일반 상태, 녹음기 목록, 최근 활동과 백업 유틸리티를 렌더링하지 않는다. 제품 제목과 안전하게 앱을 종료하는 동작만 유지한다.

### 백업 폴더 단계

- 백업 폴더가 필수라는 설명과 `백업 폴더 선택` 버튼을 표시한다.
- 앱 시작 직후 현재처럼 native 폴더 선택창을 한 번 연다.
- 사용자가 취소하면 선택창을 반복해서 띄우지 않고 차단된 화면으로 돌아온다.
- 폴더가 검증·저장되기 전에는 백업, destination 열기, 로그 열기와 별도 Settings 진입을 제공하지 않는다.

### 기본 설정 점검 단계

같은 온보딩 영역에서 다음 실제 값을 수정 가능한 형태로 표시한다.

- 선택한 백업 폴더와 `변경…` 동작
- 자동으로 백업
- WAV 백업 후 AAC-LC 128 kbps M4A로 변환
- 백업 후 macOS 휴지통으로 이동
- 로그인할 때 시작
- 편집 가능한 `DJI Mic Mini 2S` 기본 규칙이 등록되었다는 요약

새 ledger의 설정 기본값은 자동 백업 켜짐, M4A 변환 켜짐, 원본 휴지통 이동 꺼짐이다. 로그인 실행은 macOS autostart adapter에서 읽은 실제 값을 표시한다.

각 스위치는 기존의 좁은 설정 명령을 사용하며 persisted snapshot이 돌아와야 확정한다. 자동 휴지통 이동을 켤 때는 기존 안전 확인 alert를 그대로 요구한다. `설정 확인 완료` 버튼은 모든 진행 중 설정 명령이 끝났을 때만 활성화되며, 중복 클릭은 하나의 완료 요청으로 직렬화한다.

## macOS 상태바 아이콘

현재 tray는 `icon_as_template(true)`를 사용하지만 완전 불투명한 앱 번들 아이콘을 그대로 전달한다. macOS 템플릿 아이콘은 색상보다 알파 마스크를 사용하므로, 이 자산은 내부 얼굴 대신 둥근 사각형 전체로 보일 수 있다.

상태바에는 앱 아이콘의 중앙 얼굴을 그대로 알아볼 수 있는 전용 `tray-template.png`를 사용한다. 자산은 36×36 px RGBA Retina 이미지이며 다음 형태를 갖는다.

- 배경은 완전히 투명하다.
- 중앙의 둥근 얼굴 몸체만 불투명 마스크다.
- 두 눈과 입은 투명한 구멍으로 남겨 작은 크기에서도 앱 아이콘과 같은 표정을 유지한다.
- 외곽 앱 타일과 배경색은 포함하지 않는다.

`tray.rs`는 기본 window icon 대신 이 전용 자산을 compile-time에 포함해 tray 생성 시 전달한다. macOS에서는 계속 template 상태로 생성하므로 시스템이 라이트 상태바에서 어두운 심볼, 다크 상태바에서 밝은 심볼을 자동 선택한다. 앱이 실행 중일 때 테마가 바뀌어도 AppKit이 같은 자산을 다시 착색하며, 애플리케이션이 별도 테마 이벤트를 처리하거나 두 자산을 교체하지 않는다.

아이콘 디코딩이나 tray 생성이 실패하면 현재 setup 오류 보고 경계를 그대로 사용한다. 불투명한 기본 앱 아이콘으로 조용히 되돌아가지는 않는다. 상태바 클릭, popover 위치와 toggle 동작은 변경하지 않는다.

## 오류와 중단 처리

- 폴더 선택 취소는 오류가 아니며 온보딩 화면을 유지한다.
- destination 검증·저장, 설정 저장, autostart adapter, 완료 표식 저장 실패는 개인정보 없는 메시지와 지원 코드로 표시한다.
- 완료 실패 시 일반 화면을 잠깐이라도 보여 주지 않는다.
- 온보딩 중 source가 연결되어도 스캔·백업·원본 휴지통 이동 권한을 만들지 않는다.
- 앱 종료는 언제나 허용한다. 다음 실행은 저장된 상태에서 재개한다.
- 설정 점검 중 이미 저장된 개별 설정은 앱 종료 뒤에도 보존되지만, 완료 표식이 없으면 설정 점검 단계는 계속된다.

## 개인정보와 안전 경계

공개 snapshot에는 기존처럼 절대 destination 경로를 추가하지 않는다. UI에는 `선택한 백업 폴더`라는 안전한 요약만 사용하며 실제 경로는 native dialog와 Rust 내부에만 남는다. 새 명령은 경로나 임의 설정 key를 인자로 받지 않는다.

첫 실행 완료는 원본 삭제 권한과 독립적이다. 자동 휴지통 이동의 기본값은 계속 꺼져 있고, 켜더라도 녹음기별 전체 복사·M4A·source 재검증 배리어가 끝나야 한다.

## 테스트와 검증

### Rust

- 새 ledger, destination 저장 전, settings review pending, 완료 상태의 전이를 검증한다.
- destination 저장과 pending 표식의 transaction 원자성을 검증한다.
- pending 상태를 재시작했을 때 복원되는지 검증한다.
- 기존 destination과 표식 없는 ledger가 `ready`로 유지되는지 검증한다.
- 마이그레이션 destination과 사용자 설정이 변경되지 않는지 검증한다.
- pending 상태에서 수동·자동 백업이 거부되고 완료 뒤에만 허용되는지 검증한다.
- 완료 표식 저장 실패가 runtime을 `ready`로 바꾸지 않는지 검증한다.

### React와 IPC 계약

- destination 단계에서 일반 백업 화면과 동작이 노출되지 않는지 검증한다.
- 선택 취소, 선택 성공, 설정 점검, 완료 전환을 검증한다.
- 네 설정 스위치가 persisted snapshot을 반영하고 실패하면 되돌아가는지 검증한다.
- 자동 휴지통 이동 확인, 완료 중복 클릭 직렬화와 오류 표시를 검증한다.
- `needs_settings_review`가 strict DTO schema와 fixture를 통과하고 알 수 없는 필드는 계속 거부되는지 검증한다.
- IPC 명령 목록은 새 완료 명령 하나만 추가되며 임의 path/settings 명령은 허용하지 않는다.

### 상태바 아이콘

- 전용 자산이 36×36 RGBA이고 배경·눈·입에 실제 투명 픽셀이 있는지 정적 검사한다.
- `tray.rs`가 기본 window icon이 아니라 포함된 전용 자산을 사용하고 template 상태로 생성하는지 Rust 테스트 또는 source contract 검사로 고정한다.
- 설치된 앱을 라이트·다크 appearance에서 각각 실행해 얼굴 심볼, 자동 명암 반전, 클릭 후 popover 위치와 toggle을 확인한다.
- 테마를 앱 실행 중 전환해 재실행이나 수동 새로고침 없이 상태바 색상이 바뀌는지 확인한다.

### 사용자 화면과 릴리스

- 브라우저 preview에서 두 온보딩 단계의 키보드 접근성, label, focus, 작은 popover 높이와 가로 overflow를 확인한다.
- `./scripts/check.sh`, FAT32 규칙 fixture, 삭제 fixture와 기존 verifier를 통과한다.
- Headatever로 버전을 생성하고 정확히 하나의 `Backup Mic.app`과 DMG를 빌드한다.
- 번들 ID, 버전, macOS 13 최소 버전, arm64, deep strict ad-hoc 서명과 DMG를 검증한다.
- `/Users/channprj/Applications/Backup Mic.app`에 원자적으로 재설치하고 패키지·설치 실행 파일 SHA-256이 같은지 확인한다.
- 설치된 기존 사용자 ledger가 추가 온보딩 없이 현재 destination과 DJI preset을 유지하는지 확인한다.
- 설치된 앱의 상태바가 전용 얼굴 심볼을 사용하며 라이트·다크 테마에서 각각 읽기 쉬운지 확인한다.

## 완료 조건

- 새 설치는 destination과 설정 점검을 마치기 전에는 백업할 수 없다.
- 취소 후에도 차단형 온보딩이 유지되며 앱 종료는 가능하다.
- 설정 점검은 실제 값을 수정할 수 있고 재실행 뒤에도 이어진다.
- 기존·마이그레이션 설치는 추가 온보딩 없이 계속 동작한다.
- 원본 삭제 기본값과 검증·휴지통 안전 경계가 바뀌지 않는다.
- 상태바에는 앱 얼굴 심볼이 표시되고 macOS 테마 변경에 맞춰 자동 반전된다.
- 모든 소스·브라우저·fixture·패키지·설치 검증이 통과하고 Git upstream 패리티가 `0 0`이다.
